Add agent mode to Lumbre. A new project's first message proposes a plan with a design token plan (direction, palette swatches, type roles, layout sketch) to approve, edit or discard; Build mode then works in a tool loop (list, read, write, edit, delete files, add allowlisted packages, report progress, finish) inside a private per-job draft, with a live activity card and timeline, two automatic continuations and then a Continue button with an optional goal, an automatic build check of the draft copy with up to two fix rounds, and the usual diff review before anything reaches the project. The tools refuse every call that does not come from a running Lumbre build, and models without tool calling are detected and use the block format. Generated code follows new packaged guidance: `lmb-design` (adapted from Anthropic's and Vercel Labs' frontend-design skills, Apache-2.0), `lmb-tailwind` (adapted from Seth Hobson's tailwind-design-system, MIT) and `lmb-react-next` (adapted from Vercel's react-best-practices, MIT, plus Next.js 16 file conventions), with a fewer-dependencies-first rule. The package allowlists now include common libraries per stack (clsx, tailwind-merge, class-variance-authority, zod, self-hosted fonts; on React and Next.js also lucide-react, react-hook-form, @hookform/resolvers and Radix primitives), and Astro projects can enable React islands through a Lumbre-managed config change.
