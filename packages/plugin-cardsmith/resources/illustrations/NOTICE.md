## Tags

`tags` is optional per asset and drawn from a fixed lowercase vocabulary:
`kawaii`, `birthday`, `love`, `formal`, `technical`, `decoration`, `retro`, `nature`, `food`.
The catalog groups illustrations by these tags; adding a tag is a vocabulary change,
not free-form metadata.

## Color token semantics

Asset ops reference palette tokens so one drawing reads in every palette:

- `$background` — page background for the active palette; avoid as a shape fill because it
  disappears into the card background.
- `$text` — approved text ink for the active palette. Used for outlines and facial details:
  it is dark ink on light palettes and light ink on dark palettes.
- `$primary`, `$secondary`, `$accent` — semantic palette colors for shape fills.
- `$decorative` — resolves to the first entry of `palette.tokens.decorative` and **falls back
  to `$accent`** when the active palette declares no decorative colors (for example,
  `alisio-ocean`). Assets must stay legible in that fallback case.

Literal `#rrggbb` values are palette-independent and reserved for dark ink accents such as
`#181818`; prefer `$text` when the outline should adapt to dark palettes. A literal dark ink
detail is only used inside shapes whose fill stays light in every palette.

## Rendering contract

- Flat colors only: no gradients, filters, images or external SVG.
- Each asset is drawn with `path`, `rect`, `circle` and `ellipse` ops from the asset schema.
- Assets scale with uniform "contain" fit into the target box and stay legible between
  roughly 120 px and 600 px.
- Wide banners (`waves-retro`, `ribbon-banner`, `ornament-divider`) are designed for boxes
  with a similar aspect ratio; square assets tolerate any box aspect.
